## Outcome

Fewer bounded page calls can carry ordinary complete review input without
crossing the supported host's encoded-output limit or weakening any current
coverage, chronology, finding or publication obligation.

## Scope

- One shared pure paginator bounded by 16,384 UTF-16 units, 256 newlines and
  49,152 UTF-8 bytes for the **entire compact successful read response**.
- Include current `restart-required?`, escaping and id/start/end overhead;
  preserve surrogate boundaries and exact original UTF-8 reconstruction.
- Read-specific preflight in the existing OpenCode boundary uses the actual
  encoder before candidate session publication or a successful read event;
  the plugin returns the same validated string through the existing pass-through.
  Refusal follows the current failed-call/invocation law.
- Existing pure tests, actual compiled tools and optimized invocation exports
  qualify the same geometry and source revision.
- Supported effective host limits are a caller-release precondition; lower or
  unknown limits refuse deployment qualification. No dynamic negotiation or
  current caller activation is included.

## Non-goals

No source implementation in this planning PR, transitions, new review engine,
provider/model swap, filtered diff, larger timeout, weaker assessment, approval
inferred from coverage, host-limit override, caller pin update, native retry or
resume of historical sessions. No broad generic transport/test framework.

## Acceptance criteria

- [ ] Every page satisfies all three inclusive bounds using the whole actual
  encoded response, including the current chronology flag.
- [ ] Contiguous ids/offsets, no empty pages, surrogate integrity and exact UTF-8
  reconstruction hold for ASCII, Unicode, escaping, controls, CRLF, long lines
  and missing final newline.
- [ ] Oversized encoder/envelope output or encoding failure leaves the candidate
  session unpublished, records no successful read event and adds no delivery or
  assessment credit; the existing strict invocation law refuses publication.
- [ ] The accepted compiled response is exactly the preflighted encoded string,
  with no post-validation reconstruction, added fields or second JSON encoding.
- [ ] Current stale reread, failed-call, restart, five-stage, source-binding,
  unassessed-tail and confirmed-finding controls remain enforced.
- [ ] Actual compiled output is unchanged by the pinned compatible host boundary;
  the optimized public preparation/verifier uses the same page geometry.
- [ ] Exact pinned-input baseline/candidate page counts and byte equality are
  recorded without claiming a speedup or completed model review.
- [ ] Relevant current tests, lint and required builds pass with zero warnings;
  all historical evidence remains intact.
- [ ] Host compatibility and later caller/native release obligations are explicit;
  no local fixture supplies deployment or hosted approval credit.

## Verification

Preserve the observed timeout and passing baseline lossless controls. A naive
larger-unit-only candidate must fail the escaped-output boundary witness; do not
invent a failing correctness contract for the already correct old reader. Add
the design's meaningful boundary/refusal cases before the candidate, then use
existing `npm test`, `npm run lint`, `npm run test:review-input` and required builds
after canonical admission and an execution slot. No tests ran in this draft.

## Risks

UTF-16 length is not JSON UTF-8 byte size. Counting only text misses envelope
growth. A post-return host can truncate a response after a premature delivery
event. Different paginator revisions cannot share one invocation. Lower host
overrides require caller refusal; this plugin does not currently know effective
host settings. Fewer pages may increase per-page reasoning cost. If proving the
real host boundary requires a new general harness, re-scope the three-point story.
