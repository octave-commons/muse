# Audit: opencode config surface vs muse settings renderer

Walk the config docs (`opencode.ai/docs/config`) and the implementation
in `foresight/opencode` (packages/opencode/src/config) and enumerate
every config key, then check it against muse's settings pipeline
(`src/cljs/eta_mu/opencode/settings.cljc`).

## Starting observations (from the 2026-08-13 docs pass)

These keys exist upstream but are not in `top-level-order`, so muse
renders them sorted-last instead of in host-conventional position:

- `default_agent`, `subagent_depth`
- `watcher.ignore`, `formatter`, `compaction`, `attachment.image`
- `shell`, `disabled_providers`, `enabled_providers`

Unknown keys still render — the question is whether muse wants
first-class awareness (ordering, validation, fragment conventions) for
any of them.

## Acceptance

- Exhaustive key inventory: upstream schema vs muse handling, in a note
  under `docs/notes/` or the card body.
- Each gap gets its own card or an explicit "won't support" comment.
