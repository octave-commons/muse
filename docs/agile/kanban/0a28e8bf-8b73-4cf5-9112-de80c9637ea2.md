# Audit: opencode config locations and emission targets vs muse

Upstream merges configuration from multiple runtime layers: organization
API configuration, remote `.well-known/opencode`, global,
`OPENCODE_CONFIG`, project, `.opencode` directories,
`OPENCODE_CONFIG_CONTENT`, managed files, and macOS MDM. Later sources
override earlier ones for conflicting keys.

Muse emits the project `.opencode/opencode.json` during build flush. The
daemon can additionally render whatever an optional `:emit {:path ...}`
targets, but the current root does not configure that path. It has no story
for:

- `tui.json` (separate schema, deprecated keys auto-migrate)
- `OPENCODE_CONFIG_DIR` custom directories
- managed/managed-preference enforcement (would muse even want one?)
- the array-merge question across opencode's own runtime layers —
  our deep-merge now concatenates vectors inside one tree, but
  upstream's cross-file semantics for e.g. `instructions` are
  undocumented. Verify with `opencode debug config` in a two-layer setup.

## Acceptance

- Table: upstream location → muse owner (build/daemon/none) → decision.
- `opencode debug config` evidence for the cross-file array question.
