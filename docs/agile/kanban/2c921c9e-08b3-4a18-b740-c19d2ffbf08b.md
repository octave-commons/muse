## Outcome

The existing eight review tools deliver every v2 component and record matching role/span references before accepting all five ordered stages or an exact submission. Independent invocation verification can distinguish complete raw-diff, summary and log delivery/assessment from generic nonempty notes.

## Scope

Extend the existing `domain.review/begin`, page delivery/assessment state, plugin `review_begin` and current page/assessment tools, invocation law/public CJS preparation-verification exports and ordinary reviewer prompt/guide. Preserve all tool names. Derive pages by using the existing canonical lossless page function independently for each component, assigning global IDs and exact component-local/view spans; no page conflates roles. The underlying deterministic ordered view remains child A's owner interface.

Each returned page binds trusted component role/digest and byte/text span units to its exact payload. Assessment records reference that same page, component and span. Raw-diff assessment includes changed-hunk observations or a structured no-changed-hunk explanation for that slice. Summary assessment references actual gate/status or limitation fields from delivered summary spans. Log assessment references observed result/failure/environment context in delivered log spans. A typed no-relevant-evidence observation must still reference the correct delivered component/span. Define these structures and matching evidence references in the pure owner law; arbitrary nonempty text alone is insufficient. These are provenance/coverage obligations, not a claim that syntax proves the truth of every assessment sentence.

Track delivered and assessed coverage independently for each required role and aggregate pages. Empty components retain exact zero-byte identity and an explicit empty-component observation; they must not disappear from the component universe or invent a nonempty page. Complete summary/log text remains supporting material. Only original raw diff contributes changed-line locations, file statistics and raw truncation checks, even if support contains Git headers or truncation-like sentences. Existing v1 behavior remains compatible.
