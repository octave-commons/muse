## Outcome

A Muse host can opt into an authenticated Axxium MCP inbox stream and receive a wake hint for its exact configured actor and mailbox.

## Scope

Reuse the staged Axxium Streamable HTTP contract. Verify identity with the authenticated MCP tools before opening the stream. Carry a validated, local actor binding in each wake hint. The host adapter owns wake and session policy.

## Acceptance

- Verify the exact actor and mailbox and require advertised resource subscriptions.
- Open the GET stream before registering the inbox subscription. Pass only the exact MCP inbox notification to the host callback, without message payloads.
- Abort closes the stream and suppresses subsequent callbacks. Failures are visible to the caller. The receiver has no mailbox read, send, acknowledgment, polling, or replay loop.
- Prove the transport against a loopback fixture and reject a mismatched identity without opening the stream.

## Verification

Run focused ClojureScript tests against an isolated mock MCP endpoint and lint the added namespaces. Live staged host adapter testing is separate.

## Review follow-up

Verify that coalesced SSE frames still produce separate wake hints, that oversized frames close the stream, and that terminal reasons are visible to host operators. Keep unattended child-process dispatch compatible with Node's optional abort signal and document the Node minimum. Exercise the shared identity and bootstrap-file boundary and confirm that ambiguous Drive and GitHub write failures preserve the caller's request ID for reconciliation.

## GitHub comment diagnostics

Show a confirmed GitHub rejection and attach validated provider diagnostics when Axxium returns them. Keep the caller's request ID for uncertain writes. Verify both response types, older response compatibility, and one outbound request per invocation using local fixtures.

## Correlated mailbox wait

Add one opt-in wait tool that binds to the caller's existing Axxium mailbox and subscribes for inbox changes. Read a baseline before subscribing and close the gap with one catch-up read. Inspect the inbox once per valid notice after setup. Match new message IDs against an exact sender, kind and run, with an optional reply-to ID. Return one match or a bounded terminal outcome. Leave the host wake hints and mailbox data unchanged.

Verify against an isolated MCP fixture that existing mail, unrelated notices and other correspondence cannot satisfy the wait. Verify the deadline and cancellation without sending or acknowledging any messages.
